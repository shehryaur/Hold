## A. Architecture

| # | Decision | Why | Trade-off / what it costs | Confirm? |
|---|---|---|---|---|
| A1 | **HOLD is a tool gateway that implements its own tools**, not a transparent reverse proxy in front of other MCP servers | Claude Code's built-in tools (Bash, Read, Edit) never cross MCP, so a proxy can't see the attacks in your evidence. A gateway that executes the tools itself is the only design where "denied = not executed" is actually true | Loses the "drop-in proxy for any MCP server" story. ROADMAP already recommended this at 12:30 | |
| A2 | **Only three tools: `read_file`, `write_file`, `fetch_url`** | The smallest set that shows a real ALLOW (read/write) and a real DENY (network) | The agent can't list directories or search; it relies on the task and issue naming the file | |
| A3 | **No shell tool and no git tool at all** (receipt load fails if `shell_execution` / `git_push` is true) | Write + execute = arbitrary code, so a command allowlist can't contain egress. Shell-string blocklists (`"curl"`, `"nc"`) are trivially bypassed | The agent can't run tests, so its fix is unverified. Stated as a limitation | |
| A4 | **Keep `fetch_url` even though it is denied** | Without a network-capable tool, "blocked" only means "unavailable", and a judge will say "you just removed Bash" | Exposes a real HTTP client when a receipt grants a host | |
| A5 | **Add a positive control**: same call, same URL, receipt that grants the host → ALLOW | Proves the receipt made the decision, not a missing tool | About 20 seconds of demo time | |
| A6 | **`architecture.py` becomes `hold/core.py` unchanged**; `hold/server.py` is a thin MCP wrapper | Don't rewrite tested code under time pressure | Replaces the old file plan (`proxy.py`, `gate.py`, `filesystem.py`, `telemetry.py`) | |
| A7 | **The enforcement core has no MCP dependency** | It can be tested with the stdlib alone, and the MCP SDK version risk is isolated in one file | The server sketch in SPEC.md is untested against the installed SDK | |
| A8 | **Denials return an MCP tool result with `isError: true`**, not JSON-RPC error `-32003` | MCP reports tool failures this way, so the model reads the reason and continues the task (the "graceful fallback") | None meaningful | |
| A9 | **Stdlib-only reference code** (urllib, http.server, unittest) | Zero setup; runs on any machine at the venue | `clickhouse-connect` is imported only when ClickHouse is configured | |

## B. Gate and security rules

| # | Decision | Why | Trade-off |
|---|---|---|---|
| B1 | **Strict character allowlist for paths** `^[A-Za-z0-9_./-]{1,512}$` | Kills drive letters, `:` (Windows alternate data streams), `~`, `\`, NUL, spaces and Unicode lookalikes in one rule | Files with spaces or non-ASCII names can't be accessed; fine for a Python repo |
| B2 | **Reject `..`, `.`, empty segments and trailing dots instead of normalizing them** | Normalizing is where bypasses hide; Windows maps `.env.` to `.env` | `src/flask/../app.py` is denied even though it is harmless |
| B3 | **No absolute paths**; everything is relative to `workspace_root` | One root to contain, no OS-specific path handling | The agent must use relative paths (tool docstrings say so) |
| B4 | **`realpath` containment + check both the requested and the resolved path** | Catches symlink escapes and symlinks pointing at `.env` | Costs filesystem syscalls: ~0.5–0.8 ms per path decision on Windows |
| B5 | **Re-resolve right before I/O; `O_NOFOLLOW` where the OS has it** | Narrows the time-of-check/time-of-use window | Windows has no `O_NOFOLLOW`; residual race documented |
| B6 | **Default protected patterns that a receipt can extend but never remove**; protected applies to reads **and** writes | The old code skipped protection on writes; a sloppy receipt must not unprotect secrets | Less flexibility for receipt authors |
| B7 | **`.claude/**` and `.mcp.json` are protected** | Writing them would plant hooks or instructions for later agent sessions | None for the demo |
| B8 | **Protected patterns match case-insensitively; allowlists match case-sensitively** | Errs toward DENY in both directions (macOS/Windows filesystems ignore case) | `src/flask/APP.py` is denied |
| B9 | **Own glob matcher** (`**/`, `**`, `*`, `?`) instead of `fnmatch` | In `fnmatch`, `*` crosses `/`, and its case behavior depends on the OS. That caused the `src/.git/config` bypass | ~25 lines of code to maintain |
| B10 | **Exact argument schemas**: extra, missing or wrongly typed fields → DENY | Unexpected fields are an attack surface, and the old code crashed on them | Strict; the MCP SDK may already validate types (defense in depth) |
| B11 | **Gate never raises; any exception → DENY** | Fail closed | Bugs show up as denials, not crashes; check the reasons |
| B12 | **URL rules: http/https only, no userinfo, `hostname` (not `netloc`), exact host match, no suffix matching** | Blocks `allowed.com@evil.com`, `allowed.com.evil.com`, `file://` | Subdomains must be listed one by one |
| B13 | **No redirects, no environment proxies, 5 s timeout, size caps** (512 KiB read/write, 256 KiB fetch) | A redirect could move an approved request to an unapproved host; caps limit abuse | Legit redirects fail |
| B14 | **Receipt = SHA-256 digest, explicitly not a signature**; trusted because it is outside the workspace and loaded once | Honest. Real signing doesn't fit in 5.5 hours | No protection if someone with file access edits the receipt before launch |
| B15 | **Unknown receipt fields are a load error** | Typos like `"netwrok_egress"` must not silently fall back to defaults | Stricter config |

## C. Telemetry and ClickHouse

| # | Decision | Why | Trade-off |
|---|---|---|---|
| C1 | **Telemetry is a queue + background thread; `emit` never blocks or raises** | A ClickHouse outage must not slow or change a decision | Events can be dropped if the queue (10k) fills; counted in `dropped` |
| C2 | **Always write a local JSONL audit log; ClickHouse is an additional writer** | Evidence survives venue Wi-Fi or Cloud problems | Two places to look |
| C3 | **Lazy ClickHouse connection on the telemetry thread** | Connecting at import time could stall MCP startup past Claude Code's timeout | First events arrive a bit later |
| C4 | **Client-side batching (≤ 500 rows / 250 ms)** | One INSERT per event creates one part per event in MergeTree | Up to ~250 ms extra delay to the dashboard |
| C5 | **`ORDER BY (task_id, ts)`** (was `(timestamp, task_id)`) | Every dashboard query filters on `task_id` | None |
| C6 | **`DateTime64(6, 'UTC')` and latency stored as `gate_latency_ns UInt64`** | The old schema claimed microseconds but stored milliseconds; ns keeps sub-µs gate times honest | Slightly larger column |
| C7 | **`Enum8` for `decision` and `exec_status`** | ClickHouse rejects invalid values; compact | Schema change needed to add a value |
| C8 | **Added an `exec_status` column (`ok` / `error` / `not_run`)** | ALLOW ≠ success; `not_run` is the evidence that a denied call was never dispatched | One more column in the shared contract |
| C9 | **`target` is only a workspace path or `scheme://host`**; never content, URL path/query or command lines | Those fields are exfiltration payloads; logging them leaks secrets into the audit DB | Less detail for forensics |
| C10 | **Separate `hold_writer` (INSERT) and `hold_reader` (readonly) users; no credentials in the browser or in git** | Least privilege | A tiny backend or the SQL console is needed for the dashboard |
| C11 | **The ClickHouse Cloud SQL console is an acceptable fallback dashboard** | It's real data, needs no UI code, and the ClickHouse judge will recognize it | Less visual |
| C12 | **Events and table share one column list (`EVENT_COLUMNS`)**, frozen at 11:00 | Builders A and B work in parallel against one contract | Changes must be made in two places together |
